# Stafflyt Status Page

A modern, responsive status page for monitoring Stafflyt's services and infrastructure.

## Features

- 🎨 **Beautiful Design** - Matches Stafflyt's brand and design language
- 📊 **Real-time Monitoring** - Up-to-date service status information
- 📱 **Responsive** - Works seamlessly on all devices
- ⚡ **Fast** - Built with Next.js for optimal performance
- 🎯 **Accessible** - WCAG compliant design

## Technologies

- **Next.js 15** - React framework
- **TypeScript** - Type safety
- **Tailwind CSS** - Styling
- **Lucide React** - Icons

## Getting Started

### Prerequisites

- Node.js 18+ 
- npm or yarn

### Installation

1. Install dependencies:

```bash
npm install
```

2. Run the development server:

```bash
npm run dev
```

3. Open [http://localhost:3000](http://localhost:3000) in your browser

### Build for Production

```bash
npm run build
npm run start
```

## Incidents / Issues (How to post updates)

The `/incidents` (and `/issues`) pages show **GitHub Issues** from this repository (PRs are excluded). This is compatible with Upptime’s workflow (Upptime automatically opens/closes issues when a monitored service goes down/up).

### Create an incident (manual)

1. Go to: `https://github.com/amah853/status.stafflyt.com/issues/new`
2. Create a new Issue with a clear title (examples):
	- `🔴 Incident: Stafflyt Web errors`
	- `🟡 Degraded: Email delivery delays`
	- `🔧 Maintenance: Scheduled database upgrade`
3. Put the details in the issue body (impact, affected service, start time, workaround).

The issue will appear on the status site within ~60 seconds.

### Post status updates

- Add a **comment** to the issue for each update (e.g. “Investigating…”, “Identified…”, “Monitoring…”, “Resolved…”).
- Those comments appear under the incident’s **Updates** section on `/incidents/[number]`.

### Resolve an incident

- **Close** the GitHub issue when it’s resolved. The incident will show as **Resolved** on the status site.

### Rate limits (optional)

The status site uses the public GitHub API. If you hit rate limits in local dev, add a token:

1. Create `.env.local`
2. Add `GITHUB_TOKEN=...`
